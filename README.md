# work-manager-be

## OAuth 로컬 실행 설정

`oauth` 프로필과 기본 애플리케이션 실행에는 다음 환경 변수가 필요하다.

| 환경 변수 | 설명 |
| --- | --- |
| `JWT_SECRET` | 최소 32바이트 이상의 JWT 서명 비밀 |
| `GOOGLE_CLIENT_ID` | Google OAuth 클라이언트 ID |
| `GOOGLE_CLIENT_SECRET` | Google OAuth 클라이언트 보안 비밀 |
| `GITHUB_CLIENT_ID` | GitHub OAuth App 클라이언트 ID |
| `GITHUB_CLIENT_SECRET` | GitHub OAuth App 클라이언트 보안 비밀 |
| `LOGIN_SUCCESS_URL` | 로그인 성공 후 이동할 프런트엔드 URL |
로컬 값은 `.env.example`을 복사한 `.env`에 입력하고, IntelliJ 실행 구성이나 셸에서 환경 변수로 주입한다. `.env`는 Git에서 제외되므로 실제 자격 증명을 커밋하지 않는다.


### 소셜 인증 결과 상태

Google·GitHub 인증 성공 후 `security.oauth.login-success-url`에 `status` 쿼리 파라미터를 추가한다.

- `SIGNUP_REQUIRED`: 기존 회원이 없는 소셜 계정이다. 회원·소셜 계정을 저장하지 않고 로그인 토큰도 발급하지 않는다. 기존 refresh 쿠키를 삭제한다.
- `LOGIN_COMPLETE`: 기존 회원이다. refresh 쿠키를 발급하며 `/auth/refresh`로 access token을 받을 수 있다.

`status`는 화면 분기용이며 인증 근거로 사용할 수 없다. 가입 화면은 아래 약관 조회·동의 제출 API를 사용하며, 확정된 운영 약관 등록이 필요하다.


### 가입 전 임시 상태

신규 소셜 인증 결과는 `pending_registrations`에 저장하며 정식 `users`와 `oauth_accounts`는 생성하지 않는다.
`PENDING_REGISTRATION` 쿠키는 10분간 유효한 무작위 토큰이며 HttpOnly, SameSite=Lax, 기존 secure-cookie 설정을 적용한다.
Lax는 소셜 제공자에서 돌아오는 최상위 GET 콜백에 이전 쿠키를 전달해 재인증 시 이전 임시 상태를 폐기하기 위한 설정이다.
DB에는 원문 대신 SHA-256 해시를 저장하며 조회해도 만료 시간이 연장되지 않는다.
만료된 정보는 즉시 조회할 수 없고, 10분 간격으로 DB에서도 삭제한다. 기존 회원 로그인 시 해당 브라우저의 임시 상태를 폐기한다.

- `GET /auth/registration`: 유효한 쿠키로 `{name, provider, expiresAt, terms}`를 반환한다. `expiresAt`은 UTC 기준이며 응답은 `Cache-Control: no-store`다. 쿠키 누락·만료·위조 시 401이다.
- `DELETE /auth/registration`: 임시 가입 정보와 쿠키를 삭제한다. `/auth/csrf`로 발급받은 CSRF 토큰 헤더가 필요하다.

임시 쿠키는 `/users/me` 등 보호 API나 `/auth/refresh`의 인증 수단으로 사용할 수 없다.

### 약관 동의와 가입 완료

`GET /auth/registration`의 `terms`는 활성 약관의 `{id, title, version, content, required}` 목록이다. `id`는 서버의 약관 코드다.
`POST /auth/registration`은 임시 가입 쿠키와 CSRF 헤더로 아래 형태의 요청을 받는다.

```json
{"consents":[{"id":"terms","version":"v1","agreed":true},{"id":"privacy","version":"v1","agreed":true}]}
```

ID와 버전은 반드시 조회 응답을 그대로 사용한다. 필수 동의 누락·거부, 구버전, 중복 ID, 알 수 없는 ID는 400이다.
선택 동의는 거부하거나 생략할 수 있으며 생략은 미동의로 기록한다. 필수 여부와 UTC 기록 시각은 서버가 결정한다.
성공 시 회원·소셜 계정·약관 버전별 동의와 로그인 토큰을 같은 트랜잭션에 저장하고 임시 상태를 삭제한다.
응답은 204이며 refresh 쿠키를 발급하고 임시 쿠키를 제거한다. 프론트는 기존 `/auth/refresh`와 `/users/me`로 인증을 복원한다.
같은 임시 토큰은 한 번만 사용할 수 있다. 이미 소셜 계정이 생성된 다른 임시 토큰으로 가입하면 409이며 재로그인이 필요하다.
검증·저장 실패 시 회원·동의·토큰 생성을 롤백하고 임시 상태를 유지한다. 만료된 임시 토큰은 401이다.

`registration_terms`는 약관 코드와 버전별 본문을 보존한다. 개정할 때 기존 버전의 `active`를 false로 변경하고 새 버전을 별도 행으로 등록한다.
코드별 활성 버전은 하나만 유지하고, 이미 저장한 본문·제목·필수 여부·버전은 수정하지 않는다.
`registration_consents`는 사용자·소셜 계정·약관 행과 동의 여부 및 `recorded_at`을 연결한다. 미동의 선택도 서버가 기록한 UTC 시각을 저장한다.
과거 약관 행을 보존하므로 가입 당시 버전과 본문을 조회할 수 있다. 기존 회원의 동의 이력을 임의로 생성하지 않는다.

V18은 테이블만 생성하며 **운영 약관 문구는 삽입하지 않는다**. 테스트용 문구는 테스트 DB에만 존재한다.
확정된 이용약관·개인정보 안내·선택 약관은 별도 Flyway 마이그레이션으로 등록해야 한다.
필수 약관이 없거나 동일 코드에 활성 버전이 여러 개면 가입 완료를 503으로 차단한다.
약관이 비어 있으면 조회의 `terms`도 빈 배열이며 기존 프론트는 가입 안내 오류를 표시한다.


### 약관 개정과 가입의 동시 실행

가입 완료는 독립된 `REPEATABLE_READ` 트랜잭션에서 실행한다. 활성 약관 행이 조회 도중 개정되면 PostgreSQL의 직렬화 실패를 감지하여 가입 트랜잭션 전체를 롤백하고 최대 3회 실행한다.
재시도는 임시 토큰 잠금부터 시작하므로 개정된 약관 목록을 새로 조회해 필수 동의와 버전을 다시 검증한다. 누락·구버전 동의는 400, 동시성 충돌이 계속되면 409를 반환한다.
회원·소셜 계정·동의·토큰·임시 상태 소비는 각 시도의 동일 트랜잭션에 포함되어 실패한 시도의 데이터가 남지 않는다.
약관 개정 SQL이 별도 공통 잠금을 사용하지 않아도 이 검증이 적용된다. PostgreSQL 경합 테스트는 개정 트랜잭션을 커밋하지 않은 상태에서 가입 조회가 실제 잠금 대기에 들어간 것을 확인한 뒤 개정을 커밋한다.


임시 상태의 취소·재인증·만료 정리는 엔티티를 먼저 조회하지 않고 조건부 벌크 DELETE로 처리한다. 가입 완료가 같은 행을 먼저 소비해 삭제 건수가 0이어도 정상 처리하므로, 취소는 204를 반환하고 재인증의 새 임시 상태 저장은 계속 진행한다.


활성 약관 조회는 공유 읽기 잠금을 사용하여 서로 다른 사용자의 가입이 병렬로 진행되도록 한다. 기존 약관 행의 수정·삭제는 트랜잭션이 끝날 때까지 차단한다. 동일 임시 토큰의 중복 가입은 별도의 임시 가입 행 배타 잠금으로 보호하며, 약관 개정 시 목록의 일관성은 `REPEATABLE_READ`와 전체 트랜잭션 재시도로 보장한다.
